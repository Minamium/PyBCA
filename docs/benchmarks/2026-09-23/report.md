## 実装

- 1,000 ステップ単位の履歴 JSONL 保存。規則の発火は count に圧縮し、履歴リストを無制限に保持しません。
- 開始時・定期・正常終了時の原子的なチェックポイント。セル空間の原点、全状態、次のステップ、確率、試行 ID、入力・実装ハッシュ、履歴確定範囲を保存します。
- チェックポイントより後の履歴を重複させずに再実行する処理、破損検知、同じ出力への多重 writer 防止。
- int8 による省メモリ照合と候補ベースの競合判定。CUDA では候補数を GPU に保持し、候補超過時は全セル処理へ切り替えます。
- 独立試行用の Philox と試行ごとの規則順序。seed・global trial ID・ステップで決定し、試行の分割に依存しません。
- 既存の乱数と軌道を保持する `legacy` と、比較対象の `reference` 実装を選択可能。
- 実験 CLI、PBS ジョブ、比較・ベンチマークツール、モジュール別の実装説明。

## 一致・再現性の検証

以下の初回検証では、各規則が個別に発火したことまでは網羅していませんでした。
その不足を補う [全 76 規則と適用アルゴリズムの追加監査](rule-audit/report.md) を実施しました。
CPU と V100 の両方で全項目が合格しています。V100 のジョブ `236747.rokko1` は 9 月 23 日 23:18 JST に正常終了し、9 月 24 日に結果を回収しました。全 76 規則の強制発火、5,776 の順序付き規則ペア・837,520 配置、規則内・規則間競合、境界、候補超過、開始時候補の保持と試行ごとの順序を確認しています。セル値・採用候補・書込み位置・発火数を照合し、検証コードと計算コアのハッシュも CPU/GPU・現在のローカル版で一致しました。

1. Sample 全 20 条件で、旧 `_legacy`、reference、新 CUDA の各ステップを照合しました。確率 0 / 中間値 / 1、状態ゲート、確率 sweep、イベント時間窓を含みます。
2. BCA-IP 全体は **2,000 ステップ** でセル状態、採用候補、書込み位置、イベント履歴、規則発火数が一致しました。ここでは自然なイベント発火は 0 件です。[逐次比較結果](validation-v100.json)。
3. 同一ターゲットへの候補競合、境界、負の値、隅条件、書込みなしの規則を人工的に作り、40 競合ケースと 20 照合ケースを確認しました。候補容量 1 による強制オーバーフローでも一致しました。
4. BCA-IP の 44 イベントを強制的に発火させ、原点を含む座標変換とイベント書込み・履歴を旧方式と照合しました。
5. 独立乱数の CPU/CUDA 軌道、64 bit seed・試行 ID、上位ステップビット、バッチ分割を確認しました。
6. **8 試行 × 2,000 ステップ** は、1 GPU の連続実行と、4 GPU に分割して 1,000 ステップから再開した実行が一致しました。[分割・再開比較](pilot/partition-resume-parity.json)。
7. **64 試行 × 20,000 ステップ** を 4 GPU で完走。シミュレーションと保存に約 125 秒、自然発火した入力イベントは計 56 件でした。[パイロット集計](pilot/long-summary.json)。これは最適解到達の検証ではありません。
8. **16 試行 × 30,000 ステップ** を 4 GPU で連続実行し、15,000 ステップから再開する別実行と比較しました。全試行の最終状態と自然発火した **20 イベントの名前・時刻・回数** が一致しました。[再開比較](checkpoint/restart-parity.json)。連続実行のシミュレーション・保存時間は約 52 秒です。
9. 最初の定期保存前の例外、チェックポイントより先に保存された履歴、壊れたチャンク、不整合な条件、負の原点、停止要求、writer ロック、独立モードの CPU ↔ GPU 再開も試験しています。[最終保存テストのログ](final-runtime-check.txt)。

19 の runtime テストを用意しています。CPU の試験では GPU 専用の 3 件を skip し、GPU の試験ではそれらも確認しています。
追加監査ジョブでは oracle の既知例 1 件も含む計 20 件を実行し、V100 で全件合格・skip なしでした。[ログ](rule-audit/v100-tests.txt)。
既存の 20 条件の CPU parity と rule-history smoke も通過しました。wheel に `kernels.cu` が含まれることと PBS スクリプトの構文も確認しています。

## 保存時のメモリ

最終の 16 試行 / 4 GPU 検証では、各 GPU が 4 試行を担当しました。
1,000 ステップごとの 30 回の記録で、GPU の現在割当は全 rank とも **88,938,496 bytes（約 84.82 MiB）で一定** でした。
連続実行のプロセス最大 RSS は約 1.25 GB で更新されませんでした。これは初期 YAML 読込みを含む high-water mark であり、現在 RSS の連続計測ではありません。
履歴は `checkpoint/full/rank_*/manifest.json` の各 chunk の `memory` に記録しています。
