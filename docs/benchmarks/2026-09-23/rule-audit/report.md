ケース数は入力条件の数であり、複数実装との比較回数を乗じた数ではありません。同一の入力配置が別試験にも登場することがあります。

各適用試験は **セル値・採用中心マスク・書込み済みマスク**を完全一致で比較します。旧／reference／CPU sparse は各規則の適用直後も比較し、CUDA では同じ入力について最終状態に加えて全規則の採用マスク・発火カウンターを比較します。1 規則だけの試験でも CUDA の書込み結果を照合するため、個別規則の誤りを後続規則で打ち消す比較にはなりません。

候補の直接入力は、自然な回路では低確率の競合や同時照合できない規則の組合せまで検証するためです。それとは別に、全規則の照合・通常 update・確率ゲートの合成を試験しています。

## 適用アルゴリズムを同じものと判定する根拠

規則 r の書込み変位集合を D(r)、ステップ開始時に照合・両確率ゲートを通過した中心集合を M(r) とします。D(r) に含めるのは `post != pre` かつ `post != -1` の位置だけです。領域を Ω とすると、中心 c の実際の書込み先は W(r,c)＝(c＋D(r))∩Ω です。既に先行規則が書いたセルの集合を A とします。

中心 c を採用する条件は、次の両方です。

1. W(r,c) の全てのセルについて、そこへ書こうとする M(r) 内の中心が自分だけである。
2. W(r,c) と A が重ならない。

旧実装は、前向き畳み込みで書込み先の重複を数え、逆向き畳み込みで該当する中心を全て落とします。CPU sparse は、列挙した書込み先の重複数と A の参照で同じ条件を判定します。

CUDA は各書込み先 v と他の変位 d を走査して、`v-d` に別の候補があるか調べます。変位集合には重複がないので、「別の候補がある」ことと「そのセルへ複数中心が書く」ことは同値です。外側に出た書込み先は最初から除外します。競合判定カーネルが完了するまで候補マスクを変更しないため、棄却された候補の相手を後から救済することもありません。

旧方式が規則内棄却の後で規則間棄却する点も維持します。CUDA が両条件をまとめて判定しても、規則内判定は元の M(r) を参照し、規則間判定は A のみを参照するため、最終採用集合は同じです。採用後は同一規則内・先行規則間のどちらにも書込み先の重複がなく、並列書込み順による勝者選択は発生しません。

この条件とステップ開始時の同じ M(r)、同じ規則順序が与えられれば、規則適用ごとの帰納で次状態が一致します。独立試行モードは M(r) を作る乱数と試行ごとの規則順序を変更するので、旧モードと同じ seed でも軌道一致は要件にしていません。代わりに同じ独立乱数の判定・順序を与えた座標列挙との一致を確認します。

## 検証範囲と残る制限

これは付属する全規則と上記の有限な局所条件の検証です。全セル空間・全履歴・N! 通りの全規則順序を列挙した形式検証ではありません。全ての順序付きペアを検証することと、全順列を実行することも区別します。

旧実装で「角の pre=0 は不問」「十字の pre=0 は厳密な 0」「pre=-1 は厳密な −1」という仕様も、そのまま比較しています。論文の数学的定義がこれを意図しているかは別の照合事項です。

独立モードの正方形確率行列を `[T,N]` とする修正、および同一セルへ書く特殊イベントを定義順に処理する仕様は、先行の実行ガイドに記載した意図的差分です。今回の遷移規則試験と混同しません。BCA-IP の既存 44 イベントは書込み先が重複せず、先行試験で全イベントを強制発火させて比較済みです。

```sh
PYTHONPATH=src OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  python tests/test_rule_equivalence.py --device cpu --output results/rule-audit-cpu.json

qsub scripts/rokko/rule-audit.pbs
```
