判定は「同一ユニットから同じ最適解ベクトルの出力が、最終ステップTまで10万ステップ以上継続した試行」。A/Bのどちらか片方でよく、両方が満たしても1試行として数える。途中で失った最適解、判読不能を挟む区間、別ユニットへの切替えでつないだ区間は数えない。

| 条件1・N=2 | 3,000,000 | 445/512 | 86.91% |
| 条件2・N=2 | 3,000,000 | 423/512 | 82.62% |

旧条件2・N=1の初期Weightは `[4,4,5,1,1,1]` だが、reset倍率は `[4,3,2,1,5,5]`。新しい条件2・N=2は両者を一致させている。このため旧N=1は参考値とし、差をNだけの効果とは解釈しない。旧条件2の300万・600万は同じ512試行の継続であり、独立な1024試行ではない。

## 継続計算

- rokko作業ディレクトリ：`/home/IM25D029/PyBCA_workspcace/bca-ip-three-conditions-20261007`
- コピー元：`results/variants-20261007/{condition1_N1,condition1_N2,condition2_N2}`
- 継続先：`results/variants-6m-20261013/{condition1_N1,condition1_N2,condition2_N2}`
- 同じ各512試行を再開。seed `20261007`、trial ID `0..511`、`global_prob=0.5`、独立counter RNG、セル空間・規則・イベント定義・シミュレーションコアを保持。
- `--resume --steps 6000000`。stepsは追加量ではなく絶対ステップの目標。
- 各ジョブはV100 8台、64 trials/GPU、CPU 8、RAM 64 GB、Gキュー、walltime 24時間。検証ジョブの正常終了後、3条件を順に実行し同時利用は最大8 GPU。
- 履歴を1,000ステップごと、チェックポイントを10,000ステップごとに保存。上限に届かない終了を「600万完了」と扱わず、末尾監査で検出する。

元の300万結果を物理コピーし、24チェックポイントの同一性、全72,000履歴チャンクの連続性とSHA-256、seed・trial ID・実装・入力ハッシュを照合済み。準備処理は途中ファイルを再利用できるが、ハッシュ検査は省略しない。元の結果には書き込まない。

GPU検証では実際の300万時点の全1536試行のセル状態を使い、128ステップを連続実行した結果と、64ステップ後に保存・再開して128まで実行した結果を比較する。比較対象はセル、規則確率、絶対ステップ、座標原点、自然発火イベント。検証用の短い履歴は独立ディレクトリに置き、本番履歴には混ぜない。
