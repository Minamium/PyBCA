## 収集方法

本番の原子置換されるmanifestを各ランク1回だけ読み、530万／600万で終わる履歴チャンクの接頭部分を解析用manifestに固定する。履歴は本番を読み取るだけで、checkpointや本番manifestには書き込まない。各チャンクのSHA-256、範囲の連続性、記録数、試行ID、FSM／resetイベントを既存decoderで照合する。解析用manifestは再開可能なcheckpointではない。

入力・実装・seed・trial IDの同一性を検査し、実行中のN=2についても終点より後のイベントを使わない。N=1の530万での変化点は、600万の変化点を流用せず、530万までのイベントだけから再推定する。

回収したFSMイベント時刻とreset時刻、各試行の読み出しは `readout-source/` にある。元の全イベント履歴とcheckpointはrokkoの `results/variants-6m-20261013/` に保持。解析スナップショットは同じ作業ディレクトリの `results/interim-readout-20261015/` に保持している。

N=1の48,000チャンク、N=2の42,400チャンク、合計90,400チャンクのSHA-256と内容を照合した。取得した両条件の300万以前のFSMイベント・reset時刻は、前回の確定記録と配列単位で完全一致した。さらに3つの集計の計20,984流量区間について、FSMイベントから4分割カウント・解ベクトル・最適性・継続区間を別計算で照合し、全512試行と曲線の全点が一致した。N=1の530万と600万は同じ試行を異なる終点で解析したもので、独立な追加標本ではない。

関連29テスト成功。4枚の図をPNG・PDF・SVGで出力し、PNGのレイアウトを目視確認した。[検証記録](validation.json)と[イベント単位の照合](event-level-validation.json)、配布ファイルの[SHA-256](SHA256SUMS)を添付する。
